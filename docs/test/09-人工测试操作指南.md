# ESP 人工测试操作指南(上线前全流程)

> 本文档是 ESP 上线前的**完整人工测试操作执行手册**,从"前置环境就绪"到"上线 Go/No-Go"形成可执行闭环。
> 与 `docs/test/07-人工测试用例.md` 的关系:07 是"用例骨架"(三端功能 × 各模块),09 是"操作执行手册"(含前置、地址表、命令、判定、回滚、签收)。07 列"测什么",09 列"怎么测、按什么顺序、判定标准、不通过怎么办"。
> 配套自动测试:`deploy/newman/`(19/19 接口级)、`services/integration-tests/`(INT-1~4 + Pact teacher-learning 对)、`.github/workflows/ci.yml`(6 job)+ `security.yml`(3 件套)。
> 适用环境:Mac + Rancher Desktop 单节点验证拓扑(可移植到多节点生产,单节点如实记录不降级)。
> 评估视角:教授级高级工程师 / 大厂资深架构师,工业级基线。
> 日期:2026-08-13。

## 〇、本指南的执行总览(7 大阶段)

```
阶段 0  前置环境就绪检查(node/k3s/infra/seed/镜像/CI)      ← 阻断:不就绪不开工
阶段 1  Scale 恢复 18 P0 + 集群冒烟(逐服务 healthz)        ← 已在 seed 后执行
阶段 2  鉴权越权矩阵(SEC-1~4 实跑 + JWT/WS 安全)            ← 安全阻断关口
阶段 3  三端功能联调(Web/H5/小程序 × 5 模块)                 ← 人工功能主测
阶段 4  真实 AI 链路切换(ASR/TTS/LLM 批改)                   ← 默认 Mock,可选切真
阶段 5  跨服务链路联调(REST/Dubbo Triple/Pulsar/trace)        ← L2-L5 测点
阶段 6  压测 + 混沌 + 监控告警回归(可选,单节点如实)          ← 单节点降级记录
阶段 7  上线前 Go/No-Go 签收 checklist                        ← 最终关口
```

**执行节奏**:阶段 0→1→2 必须串行(前置阻断);阶段 3/4/5/6 可在环境就绪后并行子项;阶段 7 是汇总签收。预估全程一个人工测试 session:前置 30min + 安全 30min + 三端 90min + AI 30min + 链路 30min + 压测混沌 60min(可选)+ 签收 15min ≈ 4-5h。

## 阶段 2:鉴权越权矩阵(SEC-1~4 实跑,安全阻断关口)

> 这是上线前**安全阻断关口**:任一 SEC 项失败 → 上线 No-Go。
> 回填到 `docs/test/06-安全测试报告.md`(从 `_` 改为实测结果)。

### 2.1 SEC-1 WS 越权(用 A 的 token 连 B 的 session 应 403)

**前置**:已通过阶段 3 TC-W-1 拿到两个账号 A/B 的 JWT。

```bash
# 1. 用 A 登录拿 tokenA
TOKEN_A=$(curl -s -X POST http://localhost:30009/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"a@test.com","password":"test123"}' | jq -r .token)

# 2. 用 B 登录拿 tokenB,记 B 的 user_id
TOKEN_B=$(curl -s -X POST http://localhost:30009/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"b@test.com","password":"test123"}' | jq -r .token)
# B 开一个 session(假定为 session_id=SID_B)
SID_B=$(curl -s -X POST http://localhost:30080/api/sessions \
  -H "Authorization: Bearer $TOKEN_B" -d '{"scenario_id":1}' | jq -r .session_id)

# 3. WS 握手越权:用 tokenA 连 SID_B 的 WS,期望 403/4001 鉴权失败
# (wscat 或浏览器 DevTools WS frame)
wscat -c "ws://localhost:30080/ws/speech?session_id=$SID_B" \
  -H "Authorization: Bearer $TOKEN_A"
# 期望:握手 4xx 或首个 frame 返回鉴权错误;不应进入 A 可读写 B 会话的状态
```

**判定**:
- ✅ 无法用 A 的 token 操作 B 的 session(403/4001)
- ❌ A 能读/写 B 的 session → **上线 No-Go**,回 bff/gateway 鉴权 middleware

### 2.2 SEC-2 过期 JWT(401)

```bash
# 伪造一个过期 token(JWT payload exp 已过)
EXPIRED_TOKEN="eyJ...<exp in past>"
curl -s -o /dev/null -w "%{http_code}" http://localhost:30009/api/auth/me \
  -H "Authorization: Bearer $EXPIRED_TOKEN"
# 期望:401
```

**判定**:401 = ✅;200 或 403(非 401)= ❌。回填 06 SEC-2。

### 2.3 SEC-3 X-User-Id 伪造剥离

> BFF 私钥签 JWT(RS256),下游公钥验;X-User-Id 由 BFF 注入,客户端伪造应被剥离/拒。

```bash
# 客户端伪造 X-User-Id: 999999,期望下游不信任、用 JWT claim 里的 user_id
curl -s -X POST http://localhost:30081/api/learning/mastery/weak \
  -H "Authorization: Bearer $TOKEN_A" \
  -H "X-User-Id: 999999" \
  -H "Content-Type: application/json" -d '{}' | head -c 200
# 期望:返回的是 userA 的薄弱点(不是 999999),或直接 401/403 拒绝伪造头
# DB 落库 user_id 应 = A 的真实 user_id(不是 999999)
```

**判定**:user_id 落库 = JWT 真实值 ≠ 999999 = ✅(剥离生效)。回填 06 SEC-3。

### 2.4 SEC-4 镜像 secret 扫描

```bash
# 用 trivy image 扫已部署镜像,确认无 hardcoded secret(api key/private key)
# 镜像版本见 P-0-11
trivy image --secret-config .trivyignore --severity HIGH,CRITICAL <image:1.5.0> 2>&1 | grep -iE "secret|api.key|private" | head
# 期望:无 secret 泄漏告警
```

**判定**:无 secret 发现 = ✅;有命中 → 上线前清理。回填 06 SEC-4。

### 2.5 额外 SEC-5 JWT RS256 闭环(架构 P1-2 已落地核查)

```bash
# JWKS endpoint 可达
curl -s http://localhost:30009/.well-known/jwks.json | jq .keys | head -c 200
# 期望:返回 RS256 public key(JWK),下游 Go/Java/Python 用此验签
```

**阶段 2 出口条件**:SEC-1~4 全 ✅(SEC-5 知悉即可);任一 ❌ → 阶段 7 No-Go。
