# 多级缓存架构对齐核查(2026-08-03 P2-5 修订)

> 本文件是跨语言缓存契约的正式规范。P1-6 已统一三端 key 为明文 `{service}:{entity}:{id}`;
> P2-5 在此基础上固化契约文档 + value 序列化互通 + cache_name 命名注册表。

## 一、三端实现对比表

| 维度 | Java esp-cache | Python esp_cache | Go gateway-go/cache |
|---|---|---|---|
| L1 | Caffeine(Spring CacheManager) | cachetools LRUCache(降级 dict) | 自实现 LRU(map+双向链表) |
| L2 | RedisTemplate | redis.asyncio(decode_responses) | go-redis v9 |
| 两级结构 | 是 | 是 | 是 |
| 读接口 | getOrLoad(cacheName,key,loader,ttl,cacheEmpty) | get_or_load(cache_name,parts,loader,cache_empty,ttl) | GetOrLoad(ctx,cacheName,parts,loader,cacheEmpty) |
| put 接口 | 有 put(...) | 无(走 get_or_load 回填) | 无(走 GetOrLoad 回填) |
| evict 接口 | evict(cacheName,key) | evict(cache_name,*parts) | Evict(ctx,cacheName,*parts) |
| 空结果缓存 | EMPTY_SENTINEL + 短 TTL | EMPTY_SENTINEL + 短 TTL | EMPTY_SENTINEL + 短 TTL |
| 失效策略 | 删L2+删L1+**Pulsar广播**+**延迟双删(100ms)** | 删L2+删L1,**仅本地**(跨副本靠TTL兜底) | 删L2+删L1,**仅本地**(跨副本靠TTL兜底) |
| L2不可用降级 | warn+直打DB(loader) | warn+纯L1 | warn+纯L1 |
| feature flag | esp.cache.enabled=false 不装配 | CACHE_ENABLED=false 直调loader | CACHE_ENABLED=false 直调loader |

| 空 TTL | 30s | 30s(P1-6 已从 60 改) | 30s(已对齐) |
| L1 容量 | Caffeine 配置 | 4096 | 4096 |
| **key 构造** | **调用方手传明文 `{service}:{entity}:{id}`** | **`_key(cache_name,*parts)` 明文拼接 `cache_name:part1:part2`** | 明文(P1-6 已去 sha256) |

## 二、跨语言缓存契约(正式规范,P2-5 固化)

### 2.1 key 规范(三端统一)

- **格式**:`{service}:{entity}:{id}` 明文,无 hash、无前缀。
  - 示例:`learning:due:1001`、`learning:weak:1001`、`user:1001`、`writing:grade:2002`。
- **构造责任**:Java 调用方手传完整 key 字符串;Python/Go 由公共包 `_key`/`Parts` 内部拼接。三端对同一实体 `(service, entity, id)` 产出的 Redis key 字符串**必须完全相同**。
- **理由**:明文 key 可读、可 SCAN 调试、跨语言互通;sha256 不可读且跨语言实现易漂移,P1-6 已废弃。
- **遗留**:旧文档曾约定 `cacheName:sha256(parts)[:24]`,**已废弃,以本节为准**。

### 2.2 value 序列化(跨语言互通 — P2-5 新增约定)

> **这是 P2-5 发现的最严重隐患**:即便 key 已统一,Java 用 `DefaultTyping.NON_FINAL` 多态 JSON(`["com.esp.xxx.UserView", {...}]`),Python 用纯 `json.dumps`(无类型标记),同一 key 双方互读会反序列化失败。

- **约定**:跨语言共享 key 的 value **必须用纯 JSON**(无类型标记),字段名 **snake_case** 跨语言通用。
- **Java 侧落地**:`CacheConfig` 的 `RedisTemplate` 序列化器**去掉 `activateDefaultTyping`**,改用不带类型标记的 `GenericJackson2JsonRedisSerializer`(或为跨语言 key 走专用纯 JSON 序列化器)。非跨语言场景(仅 Java 内部读写的 key)可保留多态,但需在 cache_name 注册表标注 `cross-lang=false`。
- **Python/Go 侧**:已是纯 JSON,无需改。
- **契约测试**:对每个 `cross-lang=true` 的 cache_name,断言 Java 写入后 Python 能 `json.loads` 还原为等价 dict,反之亦然。

### 2.3 cache_name 命名注册表(P2-5 新增)

> 避免跨服务 cache_name 重复/冲突,所有 cache_name 必须在此登记。

| cache_name | 服务 | 跨语言共享 | value 类型 | TTL | 备注 |
|---|---|---|---|---|---|
| `learning:due` | learning-java | 否(Java 内部) | `List<UserMastery>` | 300s | 今日复习清单 |
| `learning:weak` | learning-java | 否(Java 内部) | `List<UserMastery>` | 300s | 薄弱知识点 |
| `user` | bff-java | 否(Java 内部) | `UserView` | 300s | 用户信息 |
| `learning:agg` | learning-java | 否(Java 内部) | 聚合统计 | 300s | evict 失效目标 |
| `writing:grade` | writing-py | 否(Python 内部) | 批改结果 | 300s | |
| `writing:polish` | writing-py | 否(Python 内部) | 润色结果 | 300s | |
| `writing:translate` | writing-py | 否(Python 内部) | 翻译结果 | 300s | |
| `scenarios` | gateway-go | 否(Go 内部) | 场景列表 | 300s | 静态数据 |

> 当前所有 cache_name 均为**服务内部缓存,无跨语言共享 key 场景**(各服务缓存各自业务数据)。故 2.2 的 value 序列化互通约定为**前瞻性规范**:一旦未来引入跨语言共享缓存(如 Go 网关读 Java 写的用户缓存),必须遵循纯 JSON + snake_case。
>
> value 序列化互通的**根因风险**:Java `DefaultTyping.NON_FINAL` 写入的 value,Python/Go 读到后 `json.loads` 会得到 `["类型名", {...}]` 数组而非预期对象 —— 当前因无跨语言共享 key 不暴露,但属定时炸弹,P2-5 标注为待修(建议 Java 侧去掉 DefaultTyping,统一纯 JSON)。

### 2.4 失效策略(维持现状,文档收口)

- 写后 evict **必删 L2**(三端已一致)。
- 跨副本 L1 一致性按服务形态选择:
  - 有状态多副本 Java 服务(learning-java):Pulsar 广播 + 延迟双删(强一致)。
  - 无状态计算节点(Python/Go):仅本地 evict + TTL 兜底(最终一致,TTL=300s)。
- 不强求 Python/Go 引入 Pulsar(单节点物理约束 + 无必要)。

## 三、异同结论(更新)

**相同点(语义已对齐):**
- 三端 L1+L2 两级 Cache-Aside、get_or_load + evict、空 sentinel 防穿透、L2 降级兜底、feature flag —— 全部对齐。
- **key 构造三端统一明文 `{service}:{entity}:{id}`(P1-6 完成)**。
- TTL 默认值三端统一 L2=300s、空=30s(P1-6 完成)。

**差异点(已收口):**
1. 失效策略强度:Java 强一致(Pulsar 广播),Python/Go 最终一致(TTL 兜底)—— 按服务形态选择,维持现状(§2.4)。
2. value 序列化:Java 多态 JSON vs Python/Go 纯 JSON —— **前瞻性待修**(§2.2),当前无跨语言共享 key 故不暴露。
3. put 接口:仅 Java 有显式 put —— 语义等价(put 是 getOrLoad 子能力),不强制对齐。

## 四、P2-5 改动清单

1. **本文档**:从旧 sha256 规范更新为明文 `{service}:{entity}:{id}` 正式规范 + 新增 §2.2 value 序列化互通约定 + §2.3 cache_name 注册表。
2. **value 序列化互通契约测试**:对 `cross-lang=true` 的 cache_name 断言跨语言读写等价(当前全部 `cross-lang=false`,测试为前瞻性占位)。
3. **待修项**:Java `CacheConfig` 去掉 `DefaultTyping.NON_FINAL` 改纯 JSON(消除跨语言 value 定时炸弹,建议下一窗口期执行,需评估对现有 Java 内部缓存的反序列化兼容性)。
