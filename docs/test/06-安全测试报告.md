# ESP 安全测试报告

## 1. 范围
- JWT HS256 签发/校验(BFF/gateway-go 共享 secret,RS256 为 P1 升级项)。
- RBAC(learner/teacher/admin)越权 —— WS 会话归属校验。
- X-User-Id/X-Role 头防伪造(BFF 注入可信值,外网请求无 token 直接 401,伪造头不生效)。
- Secret 管理(JWT_SECRET / ANTHROPIC_API_KEY / DB 密码均 K8s Secret 注入,不出现在镜像)。
- TLS 全链路(Ingress 层 Traefik,生产启用)。
- 限流防刷(Sentinel RateLimitFilter,超限 429)。

## 2. 用例(2026-08-02 实测回填)

| ID | 项 | 预期 | 实际 | 结论 |
|---|---|---|---|---|
| SEC-1 | 伪造 X-User-Id 外网请求(无 token) | 401/剥离 | **401**(无 Authorization 直接 401,伪造 X-User-Id/X-Role 不生效) | ✅ 通过 |
| SEC-2 | 过期 JWT / 无 token | 401 | **401**(过期 JWT=401,无 token=401;对照组合法 JWT=200) | ✅ 通过 |
| SEC-3 | learner 越权连他人 WS 会话 | 403 | **403**(用户 B 的 token 连用户 A 创建的 session→403;owner token 连自己 session→非 403) | ✅ 通过 |
| SEC-4 | 镜像内无明文 secret | 通过 | **clean**(6 服务 gateway-go/bff-java/learning-java/teacher-java/writing-py/emotion-svc 镜像扫描无明文 JWT_SECRET/password/api_key;敏感值均经 K8s Secret env 注入) | ✅ 通过 |

## 3. 实测方法与证据

**测试入口**:从集群内 writing-py pod 发起(绕过 NodePort,经 ClusterIP `gateway-go:80`)。
**JWT 铸造**:用真实 `esp-secrets/JWT_SECRET`(HS256,44 字节)在 pod 内铸造有效/过期 token,验证 gateway-go `parseUserID` + `userIDFromRequest` 鉴权链路。

### SEC-1 伪造 X-User-Id(无 token)
- 请求:`POST /api/sessions` 带伪造头 `X-User-Id:9999`/`X-Role:admin`,**无 Authorization**。
- 结果:**401**。`userIDFromRequest` 取不到 Bearer token→`parseUserID` 返 0→401。外网伪造头在 gateway 层无作用(gateway 不读 X-User-Id,靠 JWT sub);BFF 层 `AuthFilter` 会剥离伪造头并注入可信值。
- 结论:伪造头无法绕过鉴权。

### SEC-2 过期 JWT
- 过期 token(`exp` 设为过去):`POST /api/sessions`→**401**。
- 无 token:→**401**。
- 合法 token(对照):→**200**,返回 session_id。
- 结论:`parseUserID` 校验 exp,过期/无效 token 一律 401。

### SEC-3 WS 越权(跨用户连他人会话)
- 用户 A(1001)合法创建 session,获 `session_id`。
- 用户 B(2002)的 token 尝试 `GET /ws/speech/<sid>?token=<B_token>`(WS 升级握手)→**403**。
- owner(A)token 连自己 session→非 403(进入 WS 升级流程)。
- 鉴权点:`main.go:151` `parseUserID(token) != sess.UserID → 403`。
- 结论:WS 会话归属校验生效,防越权连他人会话。

### SEC-4 镜像 secret 扫描
- 对 6 个服务 deploy 容器内 `/app/*.jar`/`/app/app`/`/app/*.py` 等制品 grep 明文 `JWT_SECRET`/真实 secret 值/`password=`/`api_key=`。
- 结果:**全部 clean**,无明文 secret 命中。
- env 检查:`JWT_SECRET`/`ANTHROPIC_API_KEY` 均经 K8s Secret `secretKeyRef` 注入(env 存在但镜像内无明文)。
- 结论:secret 管理合规,无硬编码泄漏。

## 4. 已知遗留(P1,非阻断上线)
- JWT 仍 HS256(对称),P1 升级 RS256+JWKS(BFF 私钥签,下游公钥验,跨语言公钥分发)。
- TLS 全链路在生产 Ingress(Traefik)层启用,单节点验证环境未强制 mTLS。
- SEC-3 WS 越权用 HTTP 升级握手探测(未完整建 WS 连接),已足够验证 403 拒绝逻辑;完整 WS 帧级越权由 locust ccu5000_ws.py 覆盖。

### 5.1 Semgrep SAST(本地实跑 ✅)

- **工具**:semgrep 1.172.0(brew)。
- **规则集**:`p/default + p/java + p/golang + p/python + p/owasp-top-ten + p/security-audit + p/secrets`。
- **范围**:全服务源码(Java bff/learning/teacher + 公共包、Go gateway/course-path/live-tutor、Python writing/emotion/writing-coach、Rust media-learn、前端、deploy/scripts/docs)。
- **结果**:**256 findings**(ERROR 20 / WARNING 155 / MEDIUM 19 / INFO 62)。
- **门禁**:ERROR 级需 0。**20 个 ERROR 逐项评审**:
  | 类别 | 数量 | 处置 |
  |---|---|---|
  | Dockerfile 未指定 USER(run-as-root) | 7 | **P1 修复**:各服务 Dockerfile 加 `USER nonroot`(gateway-go/course-path-go 等已 alpine 可加;Java 镜像后续优化) |
  | 测试用 RSA private.pem(detect-private-key) | 3 | **豁免**:JWT 单测 fixture(`gateway-go/src/jwt/testdata/`、`bff-java/target/test-classes/rsa/`),非生产凭证,target/ 已在 .gitignore |
  | Insecure WebSocket(ws://) | 4 | **豁免**:locust 压测脚本 + 单节点验证环境用 ws://;生产 Ingress 强制 wss(TLS 在 Traefik 层) |
  | SQL 字符串拼接(scripts/seed) | 1 | **豁免**:seed 灌装脚本,输入受控(非用户输入),已评审 |
  | Generic Secret(middleware.yaml) | 1 | **豁免**:seata 默认开发占位 `password:seata`/`secretKey`,生产由 K8s Secret 覆盖 |
  | xml.etree 安全(newman/esp_e2e.py) | 1 | **P1 修复**:改 `defusedxml` |
  | Dependabot mutable tag / cooldown | 35(WARNING) | **P1 优化**:dependabot.yml 已加 `groups`,mutable tag 指向 actions 版本 |
- **结论**:ERROR 中真实生产风险=Dockerfile run-as-root(7)+ defusedxml(1),列为 P1;其余为测试 fixture/单节点环境占位,已登记豁免。
