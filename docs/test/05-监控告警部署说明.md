# ESP 监控告警部署说明

## 1. 监控栈
- **Prometheus + Grafana + Alertmanager**:helm `kube-prometheus-stack`(monitoring 命名空间)。
- **Loki + Promtail**:结构化日志聚合(各服务 JSON 日志带 trace_id)。
- **OpenTelemetry Collector**:跨服务追踪;Java agent、Python distro、Go SDK。

## 2. 指标采集
| 服务 | 端点 | 关键指标 |
|---|---|---|
| gateway-go | /metrics(promhttp) | ws_connections、frame_latency、llm_latency |
| learning-java | /actuator/prometheus | disruptor_published/dropped、db_pool、event_inflow |
| teacher-java | /actuator/prometheus | tiflash_query_latency |
| writing-py/emotion-svc | /metrics(prometheus_client) | llm_latency、rps |
| bff-java | /actuator/prometheus | sentinel_block、jwt_reject、route_rps |

ServiceMonitor 覆盖各端点。

## 3. 告警规则
| 告警 | 条件 | 严重度 |
|---|---|---|
| CCU 骤降 | ws_connections 5min 内跌 >50% | P1 |
| 5xx 风暴 | http_5xx_rate > 1% 持续 2m | P1 |
| Disruptor 丢弃 | disruptor_dropped_total 增长 | P2 |
| HPA 到顶 | kube_hpa_desired == maxReplicas | P2 |
| Pod 重启 | kube_pod_container_status_restarts > 5 | P2 |
| TiCDC 同步延迟 | ticdc_lag_seconds > 60 | P2 |
| Redis failover | redis_cluster_state != ok | P1 |

Grafana 仪表盘:CCU/RPS/延迟/DB 连接池/Disruptor 吞吐/TiCDC lag/Redis。JSON 见 `deploy/monitoring/dashboards/`。
