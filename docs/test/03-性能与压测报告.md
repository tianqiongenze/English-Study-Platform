## 4. 瓶颈与演进
- **单节点 RD 真实 CCU 上限**:WS 峰值 0、全量 dropped,5000 CCU 在单节点不可达成。生产需多节点 + HPA,压测建议分布式 Locust master+workers。
- **学情事件全 failure 排查**:`POST /api/learning/event` 296613 请求全部计 failure,实际吞吐 ~2482 ev/s。需排查是 Disruptor 满(应返 503)还是压测断言口径错误;勿误判接口 100% 不可用(续跑 B 已修 ClassCastException 500)。
- **teacher 接口 503**:`/api/teacher/classes/analytics` 与 `/api/teacher/lesson-plan` 在压测期 503(Dubbo consumer timeout 3s 致 DEADLINE_EXCEEDED)。续跑-3 已提 timeout 至 10s,1.1.2 镜像后 HTTP 200。
- **演进**:多节点部署 + HPA 恢复原 minReplicas + 分布式 Locust 重测,预期可达 5000 CCU。

## 5. 前端连调后 1000 CCU 复压(2026-08-03,分布式 Locust,frontend-react 已部署)

> 前端 React 部署(NodePort 30090,nginx 反代 Traefik Ingress)+ 前后端连调后复压 1000 CCU。
> 注:单节点 RD,分布式 Locust locust-runner pod 集群内打 Traefik ClusterIP。

### 5.1 总体结果

| 指标 | 实测 |
|---|---|
| 并发 | 1000 CCU |
| 吞吐 | 411 rps |
| P95 | 3.1s |
| 失败率 | 9.86% |

4 个用户类均分:SpeechUser / LearningEventUser / WritingUser / TeacherUser。

### 5.2 暴露的 3 个真问题

1. **/api/sessions 100% 401** —— 根因:`locustfile.py` `mint_jwt()` 用 **HS256**(`ESP_JWT_SECRET`),但 gateway-go:1.4.1 校验 **RS256**(`JWT_RSA_PUBLIC_KEY_PEM`,见 `services/gateway-go/src/jwt/validator.go` `x509.ParsePKIXPublicKey`)。HS256 token 被拒 → 401。需 locustfile 改用 RS256(集群私钥签名)。
2. **BFF auth bug** —— 空 body `{}` → 200 + token(user_id=6629298651490403112,email=null,role=learner),非空 email → 409/401。BFF 有 mock/降级鉴权行为,阻断正常 register/login 流。
3. **HPA 扩容滞后** —— learning/teacher/writing 扩到 2 副本,新 pod 0/1 starting 跟不上 AI 长尾流量。单节点资源争用,新 pod 启动慢(注册 + 资源争抢)。

### 5.3 部分缓解与根本限制

- 探针 timeout 3→8s(防高负载误杀),但单节点是根本限制。
- **单节点铁律第三次重现**:1000 CCU 饿死 VM CPU → API server TLS 握手超时(`connection refused 127.0.0.1:6443`)。需 `rdctl start` 重拉 VM + 等 k8s 组件重启恢复。

### 5.4 SLO 对照

G-01 5000 CCU 单节点不可达;1000 CCU 实测 411 rps/P95 3.1s/9.86% fail,主要失败来自 sessions 401(JWT 签法不匹配,非接口不可用)与 HPA 启动期 503。修 locustfile RS256 + BFF auth 后预期失败率显著下降。
