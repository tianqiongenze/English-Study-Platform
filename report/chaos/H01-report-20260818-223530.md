# H-01 混沌测试报告: kill 集群 Nacos
时间: 2026-08-18 22:36:02

## 测试步骤
1. force delete 集群内 Nacos pod(nacos-5d7c9b569b-9vb2v)
2. Deployment 自动拉起新 pod
3. 监控 120s + 7min 后恢复验证

## 结果

| 指标 | 结果 |
|------|------|
| Nacos 重建时间 | ~60s(Running 但 readiness 需 JVM 完全启动) |
| Gateway :30080 | ✅ 全程 HTTP 200(不依赖 Nacos) |
| BFF :30009 | ✅ 全程 HTTP 200(Dubbo 客户端本地缓存保活) |
| Java CrashLoopBackOff | ✅ 零(120s 观察期内) |
| bff-java 注册表 | ⚠ kill 后注册表清空,恢复后需客户端重新注册 |
| community-go | ⚠ Error(DB CRDB DNS 解析失败,独立于 Nacos 事件) |

## 降级评估
- **Nacos kill → Java 服务存活: PASS** (Dubbo fail-fast:false + 本地缓存)
- **恢复自动重连: PASS** (Deployment 拉新 pod,客户端自动重连)
- **注册表恢复: PARTIAL** (bff-java 未自动重新注册,需确认 fail-fast 配置)

## 发现的问题
1. bff-java desired=3 ready=1: HPA/旧RS 残留需清理
2. community-go CRDB DNS 解析失败: 独立问题,非 Nacos 相关
3. learning-java 注册表始终只有 bff-java 1 条记录: 其他 Java 服务可能未配 Nacos 注册

## 对 CRDB 迁移的启示
1. 集群 Nacos 是 standalone(Derby + PVC),kill 后 pod 重建可自愈
2. 迁移 CRDB 需改 Deployment env(替换 Derby→PostgreSQL),不需重启 Java 服务
3. 迁移期间 Nacos 需要重建注册表,Java 服务客户端自动重连即可
4. 宿主 Nacos 可作为 CRDB 迁移失败的回滚锚点
