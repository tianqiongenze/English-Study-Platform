## 1. 背景与愿景

### 1.1 行业背景
现代 AI 英语教育平台已远超传统"背单词软件",依托大语言模型(LLM)、自适应算法与语音识别技术,构建全方位智能教学体系,正从"工具化"向"人格化"演进——成为一个 24h 在线、永不疲倦、最懂学习进度的私人教练(Home-Tutor)。行业趋势:多模态交互(数字人)、智能体(Agent)主动编排、HTAP 数据底座支撑实时学情分析、异地多活保障可用性。

### 1.2 产品愿景
构建一套面向 C 端学习者 + B 端教师的双角色、多模态、自适应、异地多活的 AI 英语教育平台 **English-Study-Platform(ESP / Home-Tutor)**,让每个用户都拥有一个"懂自己进度、会情绪共鸣、能实时纠错、有数字人形象"的 AI 英语私教。

### 1.3 价值主张
| 角色 | 痛点 | ESP 价值 |
|---|---|---|
| 学习者 | 找不到陪练对象、被纠正时社恐、遗忘曲线无法管理、缺乏陪伴感 | 24h AI 陪练 + 数字人 + 即时纠错 + 艾宾浩斯精准复习 + 情绪共鸣 |
| 教师 | 教案耗时、批改繁重、共性难点难定位 | 一键教案 + 90% 自动评阅 + 全班学情 OLAP(TiFlash) |
| 平台 | 高并发长连接难支撑、读写互相拖累、单区故障 | 5000 CCU 无状态网关 + HTAP 读写分离 + 异地多活容灾 |

## 2. 目标用户与画像

### 2.1 角色与画像
| 角色 | 标识 | 典型画像 | 设备偏好 |
|---|---|---|---|
| 学习者 Learner | C 端 | 18-35 岁,备考托福/雅思/求职,碎片化学习,日活,关注提分效率 | 移动 H5 为主、Web/小程序辅助 |
| 教师 Teacher | B 端 | 高校/培训机构英语教师,管理 1-N 个班级,关注教学效率与学情可视 | Web 桌面为主(教案/评阅编辑器) |
| 管理员 Admin | 平台 | 管理用户、场景内容、配额、监控告警 | Web 后台 |

### 2.2 核心用户旅程
1. **学习者(口语闭环)**:登录 → 初测定位薄弱点 → 选场景创建会话 → 数字人打招呼 → 说话/打字 → AI 纠错+回复+TTS驱动唇形 → 卡壳触发智能体 hint → 结束生成笔记 → 学情事件入队 → 复习推送。
2. **学习者(写作闭环)**:输入题目+作文 → 写作智能体实时建议 → 提交批改 → 评分+语法+连贯性 → 翻译精读生词。
3. **学习者(自适应闭环)**:初测 mastery 基线 → 练习上报学情事件(Disruptor)→ 动态难度调节 → 到期复习 → 路径智能体再规划。
4. **教师**:登录 → 输入主题生成教案(智能体)→ 布置作业 → 触发自动评阅(写作智能体)→ 查看班级共性难题(TiFlash OLAP)→ 终审作业。

### 2.3 北极星指标
- 学习者周活跃留存 W4 ≥ 35%(长线);日均练习时长 ≥ 15min。
- 教师单次作业批改耗时下降 ≥ 80%(自动评阅覆盖 90%)。

## 3. 产品范围

### 3.1 六大功能模块(对齐 PDF + 数字人/智能体)
| 模块 | 一句话 | 对应服务 |
|---|---|---|
| M1 沉浸式 AI 口语陪练 | 多场景角色扮演 + 即时纠错 + 启发式引导 + 数字人 | gateway-go + emotion-svc |
| M2 个性化自适应学习路径 | 知识图谱 + 动态难度 + 艾宾浩斯复习 + 学习路径智能体 | learning-java |
| M3 智能写作辅助与深度批改 | 语义润色 + 逻辑评估 + 翻译精读 + 写作智能体 | writing-py |
| M4 全能型教学辅助工具(教师端) | 一键教案 + 学情大数据 + 智能评阅 + 教案智能体 | teacher-java |
| M5 情感化与多模态交互 | 情绪感知 + 视觉辅助 + 数字人表情驱动 | emotion-svc |
| M6 数字人与智能体编排(横切) | 数字人形象/唇形/表情;四类智能体主动建议 | 前端 + 各服务 + LLM |

### 3.2 本期范围(In Scope)
- 六大模块端到端核心链路(MVP)。
- 5000 CCU 在线 + 学情事件 ≥5000 ev/s 的工程化能力。
- 三端交付:Web(全功能)、H5(移动全功能+教师只读)、小程序(学习者核心)。
- 数字人(唇形/表情)与四类智能体编排。
- 真实 LLM 走 Anthropic Claude(复用本机 Claude Code 端点);ASR/TTS Mock(接口对齐)。
- 真 TiKV 异地多活 TiDB 集群(PD3+TiKV3+TiDB2+TiFlash2 + TiCDC 跨区);Redis Cluster;Pulsar 集群。
- TDD 全流程、K8s 生产部署、Locust 压测、HPA 弹性扩容、企业级监控、混沌工程。

### 3.3 非本期范围(Out of Scope)
- WebRTC 真实音视频流(预留升级)。
- 真实情绪模型与图像生成(接口对齐,本期占位)。
- 多租户 SaaS 计费体系。
- 三区互为主写的强一致异地多活(本期 aws 主写 + azure/gcp 只读副本,异步 TiCDC)。

## 6. 用户体验原则
1. **低焦虑**:AI 陪练不评判,纠错轻量、可忽略,卡壳有 hint 兜底,数字人提供陪伴感。
2. **即时反馈**:口语回复、纠错、难度调整均亚秒级响应。
3. **个性化可见**:学习路径、薄弱点、复习计划对用户透明可解释;智能体建议带"💡"并显示依据。
4. **教师减负**:90% 评阅自动化,教师只做终审与共性讲解。
5. **多端一致**:Web/H5/小程序进度同步,数字人三端可呈现。

## 9. 风险与约束
- **R1 LLM 成本与限流**:压测切 mock 模式规避费用与限流;真实调用复用本机 Claude Code 端点。
- **R2 真实音视频**:本期 ASR/TTS Mock,WebRTC 预留。
- **R3 高并发长连接**:5000 CCU 需无状态网关 + Redis 会话外置 + HPA。
- **R4 读写互相拖累**:高频学情写 + 学情分析读,须读写分离 + TiFlash 列存。
- **R5 异地多活资源**:单节点 RD 承载有限,真集群在 aws 主区 + TiCDC 跨区只读副本。
- **C1 多语言微服务**:Go 实时面 / Java 业务面 / Python AI 面,按最优选型。
- **C2 基础设施复用**:容器中已有 TiDB/Redis/Pulsar 则重用,不重复部署。
