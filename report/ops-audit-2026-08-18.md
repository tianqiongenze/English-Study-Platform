# ESP 基础设施运维审计报告

> 审计日期: 2026-08-18 | 审计人: infra-expert | 环境: Rancher Desktop 单节点 (9核/30GB)
> 对标目标: 5000 CCU 生产级部署

## 1. CockroachDB (CRDB) — 重点审计

### 1.1 集群拓扑

| 项目 | 现状 |
|------|------|
| 版本 | v24.3.11-arm64 |
| 节点数 | 3 (crdb-0/crdb-1/crdb-2) |
| Namespace | esp-crdb |
| podManagementPolicy | Parallel |
| Pod Anti-Affinity | preferredDuringScheduling (soft, weight=50) |
| Security | --insecure |
| PVC | 3 x 20Gi (local-path StorageClass) |
| Locality | zone=z1/z2/z3 (pod ordinal mapping) |
| 磁盘 | 354GB total, 276GB used, **60GB free (83%已用)** |

### 1.2 资源配置

```
Pod资源: requests=1CPU/2Gi, limits=2CPU/4Gi (per node)
启动参数: --cache=.25Gi --max-sql-memory=.25Gi
实际用量: crdb-0=899m/1772Mi, crdb-1=322m/1537Mi, crdb-2=890m/1817Mi
```

**问题**: 实际内存 1.7-1.8Gi/4Gi limit, 启动参数 cache/.25Gi 过于保守，5000 CCU 下很可能 OOM。

### 1.3 Cluster Settings

| Setting | 当前值 | 生产推荐 | 评估 |
|---------|--------|----------|------|
| `kv.closed_timestamp.target_duration` | 3s | 3s | OK |
| `admission.kv.enabled` | true | true | OK |
| **`sql.defaults.statement_timeout`** | **0 (无限制)** | **30s-60s** | **P1** |
| **`sql.defaults.idle_in_transaction_session_timeout`** | **0 (无限制)** | **5min** | **P0** |

### 1.4 Zone Config 问题

- sessions 表 table-level zone config 覆盖了 database-level, constraints=[] → 200万行大表无 zone 约束
- 大部分 esp_* 数据库无显式 zone config

### 1.5 数据分布

```
Range: store1=98, store2=98, store3=98 (均匀)
主要大表: learning_events 1000万行, user_mastery 500万行, session_turns 500万行
```

### 1.6 备份状态

**没有配置任何用户级 BACKUP 计划 — 零备份策略**

### 1.7 CRDB 审计结论

| 问题 | 优先级 | 预期收益 |
|------|--------|----------|
| 零备份策略 | **P0** | 防止数据丢失 |
| 磁盘 83% (60GB余) | **P0** | 防止磁盘满节点死亡 |
| idle_in_transaction_session_timeout=0 | **P0** | 防止连接泄漏/长事务阻塞 |
| statement_timeout=0 | **P1** | 防止慢查询耗尽资源 |
| sessions 表 zone config 覆盖 | **P1** | 优化大表 lease 分布 |
| 启动参数 cache/.25Gi 过于保守 | **P1** | 利用新增内存上限 |
| --insecure 模式 | **P1** | 安全基线 |
