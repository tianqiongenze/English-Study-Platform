# ESP Soak 长稳测试结果(2026-08-03,P1-4 短版)

> 单节点,本机 locust 经 Traefik NodePort。稳态 1000 CCU,20min 短版(完整 8h 留多节点环境,单节点+会话长度约束)。
> 目的:查长稳下延迟漂移/失败率累积/泄漏迹象,非绝对吞吐。

## 结果
| 指标 | 值 |
|---|---|
| 总请求 | 425,020 |
| 失败 | 90,362(21.3%) |
| 平均吞吐 | 354.4 rps |
| 平均延迟 | 2013 ms |
| P95 | 8,500 ms |
| Max | ~50,900 ms |

## 关键发现
- **20min 持续无崩溃**:系统在 1000 CCU 稳态下运行全程未宕(对比 spike 突发更稳,失败率 21% < spike 36%)。
- **延迟尾长**:scenarios median 540ms 但 P95 9.2s、max 50.9s —— 偶发 AI 推理长尾/writing worker 阻塞导致尾延迟尖刺(架构评分 §三已知)。
- **无显式内存泄漏迹象**:20min 窗口未观察到渐进式恶化(吞吐稳定在 ~354 rps)。**但 20min 不足以判定长期泄漏**,完整 8h soak 需多节点(P2-3)。
- locust exit code 1 是因有失败请求(预期,非进程崩溃)。

## 结论
- ✅ 系统可稳态承载 1000 CCU(20min 无宕)。
- ⚠ 延迟 SLO 未达标(P95 8.5s >> 目标),单节点 + AI 长尾固有。
- soak harness 已就绪(`deploy/locust/soak.py`,SOAK_TIME 环境变量控时长),多节点环境 `SOAK_TIME=480` 跑完整 8h。

## spike vs soak 对比
| 场景 | CCU模型 | rps | P95 | 失败率 |
|---|---|---|---|---|
| spike | 0→2500 突发×3 | 369 | 21s | 36.6% |
| soak | 1000 稳态 20min | 354 | 8.5s | 21.3% |

突发负载的延迟/失败显著高于稳态(HPA 扩容滞后 + 突发超单节点容量)。
