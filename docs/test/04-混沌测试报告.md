# ESP 混沌测试报告

## 1. 范围(ADR-15)
单节点 RD 脚本化混沌;脚本见 `scripts/chaos/`。

## 2. 场景与结果

> 执行环境:单节点 Rancher Desktop(6 CPU/14GB),ns `esp-prod`,2026-07-31 续跑-3 执行。
> RTO 原始记录:`report/chaos-rto.txt`;详细日志:`report/chaos-*.log`。

| 场景 | 注入 | 预期 | 实际恢复时间 | 数据一致性 |
|---|---|---|---|---|
| Pod kill | delete gateway-go pod(replicas=2) | WS 重连无 5xx 风暴 | **RTO 1s**(副本自愈,另一实例立即接管) | ✅ 无丢失,WS 客户端重连 |
| Redis 下线 | redis_down.sh 注入 20s(REDIS_HOST→127.0.0.1:1)+ rollout 恢复 | 会话查询降级不崩 | **~44s**(含 20s 注入 + rollout 恢复 ~24s) | ✅ Redis PVC+AOF 持久化,重启后 key 存活 |
| TiDB 下线 | tidb_down.sh 注入 20s(读副本不可达)+ learning-java 滚动恢复 | 503+Disruptor 缓冲,恢复后 drain | **~100s**(新 pod Nacos/Dubbo 注册慢,单节点资源紧张) | ✅ Disruptor 缓冲事件,恢复后 drain 落库 |
| 延迟注入 | tc netem delay 500ms | Sentinel 降级触发 | **跳过**(tc not found / 容器无 NET_ADMIN,单节点 RD 约束) | N/A |
| BFF kill | (并入 Pod kill 用例,gateway-go 已覆盖自愈模式) | REST 短暂 502,HPA 替换 | 同 Pod kill RTO 量级 | ✅ |
| 跨区断网 | NetworkPolicy 断 azure | 异地只读停同步,主区正常 | **跳过**(RD CNI 不强制 NetworkPolicy,apply 成功但不生效,如实记录) | N/A |

### 关键修复(执行中发现的脚本 bug)
- `redis_down.sh` 在 `set -u` 下 `${Dur}`(应 `${DUR}`)unbound,致注入后恢复段未执行,gateway-go 残留 `REDIS_HOST=127.0.0.1:1`。已手动 `set env` 恢复 + 脚本 typo 修复固化。
- 教训:chaos 脚本失败后必查 env 是否残留。

### 单节点约束说明
- `latency_inject` 与 `net_partition` 在单节点 Rancher Desktop 上因 tc 缺失 / CNI 不强制 NP 无法真正注入,如实记录为"跳过"而非伪造结果。生产多节点环境需补测这两项。
